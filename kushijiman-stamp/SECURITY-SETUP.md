# 本番化の進め方（セキュリティ優先）

現在の GitHub Pages は**デザイン／操作デモ**です。ポイントがブラウザの localStorage にあるため、本物の付与権限として利用しないでください。

## 用意したもの
- `secure-schema.sql` : 会員・店舗スタッフ・付与履歴のDB定義とRLS、スタッフ専用RPCをコードとして準備
- このSQLは **まだ Supabase に実行していません**。どのアカウント／プロジェクトを使うか未確定のためです
- GOLD FIRST のDBには手を触れません

## 権限
- お客様は本人のカード・付与履歴だけ読める。ブラウザからポイント UPDATE は禁止
- スタッフは管理者が登録した店舗でだけ付与可能。会員ID、店舗コード、一意のリクエストIDを送る
- 同時付与ロック・連打再送の二重付与防止・誰がどの店で付与したかの追跡

## 未完了

- Auth（お客さん／店員ログイン）とカード登録API
- QRコードの真正性・期限対策
- 500円／1500円の引き換え処理と累計完成枚数
- 店長の承認付き取り消し、店舗横断履歴
- 現行の紙カードからの引継ぎ

**本番運用前に上記全項目を実装・テストする必要があります。**

最初に専用 Supabase プロジェクトを決め、そこで SQL と拒否テストを行います。GitHub Pages に service_role / secret key は絶対に置きません。
